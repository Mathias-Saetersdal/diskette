# Stage 1 report: build-time asset derivatives

## What was built

`scripts/derive-assets.ts`, run with tsx. It reads the committed originals
under `public/assets`, writes two WebP derivatives per original into
`public/assets/derived`, and writes one metadata record per original into
`src/data/assets.generated.json`. No component, no entry data and no
`assetUrl.ts` change. No network access of any kind.

The serve root is discovered, not assumed: the script probes the first
entry's own cover path from `src/data/lists.ts` under `public/`, `static/`
and the repo root, and fails loudly if none contains it. It resolved to
`public/`, so the path strings in `lists.ts` map to `public/assets` and the
derivatives land at `public/assets/derived`, served at `/assets/derived/...`.

Skipped as instructed: `.DS_Store` files, the `marks` directory, and the
`derived` output tree itself. `src/assets/` never enters the walk because the
walk is rooted at the served assets directory.

Before deriving anything the script verifies that every path string in
`lists.ts` (`cover`, `disc`, `spine`, `back`) exists on disk and exits
non-zero listing every missing path if not. Any read, decode, resize or
write error prints the path and the error and exits non-zero. After encoding
an asset whose input had alpha, the output is read back with sharp and the
run aborts if `hasAlpha` is gone.

Flags: `--force` regenerates everything. `--only=<substring>` processes only
matching keys, in the same `--only=` form `scripts/fetch-assets.ts` already
uses (a space-separated `--only <substring>` is accepted too). A default run
is idempotent: a derivative newer than its original is skipped and its
existing JSON record is carried forward. A record whose original vanished is
dropped with a printed warning, never silently.

## Wiring

- `package.json`: `"derive-assets": "tsx scripts/derive-assets.ts"` and
  `"prebuild": "npm run derive-assets"`, so `npm run build` regenerates.
- `.gitignore`: added `public/assets/derived/`.
- `thumbhash` installed as a devDependency. `sharp` was already a
  devDependency (`^0.35.3`) from the fetch script, so nothing changed there.

## Deviations from the task text, with reasons

- The task said to add `assets/derived` to `.gitignore`. A gitignore pattern
  containing a slash is anchored to the repo root, so that literal line would
  not match `public/assets/derived/`, which is where the derivatives have to
  live to be served at the `/assets/derived/...` paths the records carry. The
  line added is `public/assets/derived/`. Confirmed with `git check-ignore`.
- The task said to add `.DS_Store` to `.gitignore`. It is already there
  (line 19 of the existing file), so no second line was added.

## Typecheck

`npx tsc --noEmit` passed with exit 0. The root config is solution-style, so
`npx tsc -p tsconfig.node.json`, the project that covers `scripts/`, was also
run directly and passed with exit 0.
